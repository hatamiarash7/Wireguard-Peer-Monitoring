# Repository guidance

## Development and verification

- Use Python 3.14.0 (`.python-version`, Dockerfile). Install with `make dev`; Poetry keeps the environment in `.venv`. The lockfile was generated by Poetry 2.1.4, while Docker pins Poetry 1.8.2; account for that mismatch when changing dependencies or the image.
- Run lint as `poetry run make lint`: the Makefile invokes `python3 -m pylint` without activating Poetry. Focused check: `poetry run pylint --rcfile=.pylintrc monitoring/<file>.py`.
- `make test` runs pytest, but no tests are currently checked in. New tests belong in `tests/`; focused invocation: `poetry run pytest tests/test_<name>.py::test_<name>`. Pytest's asyncio mode is `auto`.
- `.github/workflows/release.yml` runs on published releases and builds/pushes Docker images; it does not run lint or tests. Run relevant checks locally.

## Running locally and in containers

- Copy with `cp config.toml.example config.toml` (the README's copy command reverses the example filename), then configure Redis, the WireGuard interface, and the manager webhook. Run `CONFIG_FILE=config.toml make run`.
- The application reads `CONFIG_FILE`, defaulting to `/app/config.toml`. Compose's `CONFIG_PATH` variable is ignored; its config mount works through that default path.
- Compose uses a published monitoring image, not the working tree. Inside Compose, set `[redis].host = "redis"`; the example's `localhost` is for a Redis server reachable on the application's own host. Compose does not publish Redis's port to the host.
- Live events require Linux WireGuard dynamic-debug logs forwarded by rsyslog over UDP; follow the README's host setup. Synthetic messages must include the configured interface prefix, e.g. `wg0: Receiving handshake initiation from peer 12 (192.0.2.1:51820)` for interface `wg0`.

## Runtime and test boundaries

- `python -m monitoring` enters `monitoring/__main__.py`, installs signal handlers, then starts the blocking UDP loop and Prometheus HTTP server in `main.py`. Redis operations are synchronous; webhooks run on a queue-backed daemon thread.
- Importing any `monitoring` submodule executes `monitoring/__init__.py`: it configures logging, loads TOML (exiting on a missing/invalid file), starts the notifier, and constructs the Redis client. Set `CONFIG_FILE` before imports in tests and isolate notifier/Redis side effects. `handler.py` also compiles its interface filter at import time, and `prom.py` registers global metrics.
- To add an event, update `handler.EVENTS` and the named function in `action.py`: dispatch uses `getattr`, and regex capture groups are the action's input contract. Group 1 is also the peer-ID metric label.
- Redis hashes use `wireguard_peer:{peer_id}`. Endpoint comparisons expect byte keys/values from `hgetall`; preserve that in fakes. Handshakes update `handshake`, keepalives update `keepalive`, and a new/changed endpoint queues a webhook payload of `{"peer": "ip:port"}`.
